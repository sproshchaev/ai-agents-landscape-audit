[![check](https://github.com/sproshchaev/ai-agents-landscape-audit/actions/workflows/check.yml/badge.svg)](https://github.com/sproshchaev/ai-agents-landscape-audit/actions/workflows/check.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Эксперимент к статье на Хабре
«[AI-агентов в компании уже десятки, а в архитектурном репозитории их ноль](https://habr.com/ru/companies/otus/articles/1088908/)».

Архитектурный репозиторий синтетической компании выглядит аккуратно: 36 приложений,
у 35 есть бизнес-владелец, все 41 интеграция идут по утверждённым каналам, агентов
с типом `ai-agent` нет ни одного. Скрипт собирает агентов по фактическим следам —
MCP-конфигам команд и журналу LLM-шлюза, дополняет их сведениями из IAM и сверяет их
с репозиторием по шести ошибкам.

## Быстрый старт

Нужен только `python3`, сторонние пакеты не используются.

```bash
git clone https://github.com/sproshchaev/ai-agents-landscape-audit.git
cd ai-agents-landscape-audit
./run.sh
```

`run.sh` запускает `audit.py` и сверяет вывод с `expected.txt`, при расхождении код выхода 1. Пограничные случаи: `python3 -m unittest test_audit.py`.
Строка на каждого агента: `python3 audit.py --details`.

## Как устроено

- `data/repository.json` — архитектурный репозиторий: бизнес-возможности, приложения
  с владельцами и хостами, интеграции, стандарты (каналы интеграции и MCP-шлюз).
- `data/runtime/mcp/<команда>.json` — MCP-конфиги агентов по командам: назначение,
  бизнес-возможность, учётная запись, подключённые MCP-серверы.
- `data/runtime/service_accounts.csv` — учётные записи, под которыми работают агенты:
  сервисная или человека, включена ли, права.
- `data/runtime/llm_gateway.csv` — журнал LLM-шлюза за 90 дней: дата, учётная запись,
  агент, число запросов.
- `audit.py` — проверка репозитория и шесть проверок агентов.
- `test_audit.py` — пограничные случаи проверок 1–6, которых нет в синтетических данных.
- `generate.py` — генератор данных с фиксированным seed. Данные уже лежат в `data/`,
  CI проверяет, что генератор воспроизводит их байт в байт.

Правила проверок:

1. ключ агента не найден в поле `runtime_key` ни одного элемента репозитория либо найден у элемента с типом не `ai-agent`;
2. бизнес-владельца нет ни в репозитории, ни в поле `business_owner` MCP-конфига. Поле `technical_owner` (руководитель команды) аудит намеренно не читает: технический владелец бизнес-владельцем не считается;
3. хотя бы одна учётная запись агента, заявленная в MCP-конфиге или замеченная в журнале шлюза, не сервисная: человека или неизвестная. В данных это только учётки людей, неизвестные учётки проверяются в `test_audit.py`;
4. хотя бы один удалённый MCP-сервер подключён не по HTTPS к хосту `api-gw.corp.local` на порту 443. Локальные серверы через stdio (поле `command`) адреса не имеют и пропускаются, удалённый сервер без адреса считается подключённым мимо шлюза. Это статическая проверка конфигурации, а не доказательство того, что трафик идёт через шлюз;
5. бизнес-возможность агента закрывают агенты двух и более команд;
6. последний вызов через LLM-шлюз старше 30 дней до даты аудита (31.10.2026), а учётная запись не подтверждена как отключённая. Агент без единого вызова в журнале сюда не попадает: его активность неизвестна, а не нулевая. Это повод для проверки владельцем, а не основание отключать агента автоматически: квартальные и резервные агенты молчат дольше.

## Границы

Данные синтетические, доли ошибок заданы в генераторе. Агенты ищутся по двум источникам, MCP-конфигам и журналу LLM-шлюза, а выгрузка учётных записей только дополняет найденное. Агент без MCP, который ходит к модели в обход шлюза, этой сверке не виден. Проверка 3 смотрит только тип учётки: уникальность сервисной учётки и соответствие прав (`scopes`) инструментам не проверяются. Пересечения в проверке 5 ищутся на уровне бизнес-возможности, сценарии не моделируются, поэтому это кандидаты на разбор. Команда агента, найденного только в журнале шлюза, выводится из ключа `agt-<команда>-NN`. Цифры показывают, что находит
сверка репозитория с фактическими следами, а не статистику по рынку. В реальной компании
источники будут другими: каталог MCP-серверов, IAM, журналы шлюза, счета провайдеров
моделей. Метод тот же: агенты ищутся там, где они оставляют следы, а не в репозитории.
