[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Эксперимент к статье на Хабре
«[AI-агентов в компании уже десятки, а в архитектурном репозитории их ноль](https://habr.com/ru/companies/otus/articles/1088908/)».

Архитектурный репозиторий синтетической компании выглядит аккуратно: 36 приложений,
у 35 есть бизнес-владелец, все 41 интеграция идут по утверждённым каналам, агентов
с типом `ai-agent` нет ни одного. Скрипт собирает агентов по фактическим следам —
MCP-конфигам команд, сервисным учётным записям и журналу LLM-шлюза — и сверяет их
с репозиторием по шести ошибкам.

## Быстрый старт

Нужен только `python3`, сторонние пакеты не используются.

```bash
git clone https://github.com/sproshchaev/ai-agents-landscape-audit.git
cd ai-agents-landscape-audit
./run.sh
```

`run.sh` запускает `audit.py` и сверяет вывод с `expected.txt`, при расхождении код выхода 1.
Строка на каждого агента: `python3 audit.py --details`.

## Как устроено

- `data/repository.json` — архитектурный репозиторий: бизнес-возможности, приложения
  с владельцами и хостами, интеграции, стандарты (каналы интеграции и MCP-шлюз).
- `data/runtime/mcp/<команда>.json` — MCP-конфиги агентов по командам: назначение,
  бизнес-возможность, учётная запись, подключённые MCP-серверы.
- `data/runtime/service_accounts.csv` — учётные записи, под которыми работают агенты:
  сервисная или человека, включена ли, права.
- `data/runtime/llm_gateway.csv` — журнал LLM-шлюза за 90 дней: дата, учётная запись,
  агент, число запросов.
- `audit.py` — проверка репозитория и шесть проверок агентов.
- `generate.py` — генератор данных с фиксированным seed. Данные уже лежат в `data/`,
  CI проверяет, что генератор воспроизводит их байт в байт.

Правила проверок:

1. ключ агента не найден в поле `runtime_key` ни одного элемента репозитория;
2. бизнес-владельца нет ни в репозитории, ни в MCP-конфиге команды;
3. учётная запись агента имеет тип `human`;
4. хотя бы один MCP-сервер подключён не через `api-gw.corp.local`;
5. бизнес-возможность агента закрывают агенты двух и более команд;
6. последний вызов через LLM-шлюз старше 30 дней до даты аудита (31.10.2026), а учётная запись включена.

## Границы

Данные синтетические, доли ошибок заданы в генераторе. Цифры показывают, что находит
сверка репозитория с фактическими следами, а не статистику по рынку. В реальной компании
источники будут другими: каталог MCP-серверов, IAM, журналы шлюза, счета провайдеров
моделей. Метод тот же: агенты ищутся там, где они оставляют следы, а не в репозитории.
